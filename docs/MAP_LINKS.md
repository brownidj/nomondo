# Restaurant map links — 10 November 2026

Goal: pressing the existing address pin opens a map for the restaurant while
preserving address tooltips. Scope: map launch helper, pin behaviour, dependency
and platform registration generated by Flutter, and documentation. No database
or service changes are required.

`flutter_app/lib/services/restaurant_maps.dart` constructs an encoded search
from restaurant name, address, city and country. Blank and Not listed address
values have no map action. Native macOS/iOS use the Apple Maps URL scheme, with
an HTTPS Apple Maps fallback if launching fails. The legacy query form supports
the project's macOS 12 deployment target. Web always uses a Google Maps search
URL with `api=1`, opened directly through package:web in a new tab from the user
gesture. Conditional imports keep browser APIs out of native builds. Web map
launching does not depend on url_launcher plugin registration. The new tab uses
noopener/noreferrer; its unavailable window handle is not treated as failure. Other native platforms open that URL externally.
Missing app handlers/launch errors show a short error message in BeneEde.

The existing Tooltip now uses hover and long-press rather than consuming taps.
The icon's accessible label describes its Maps action. Both table and card views
share this implementation. Phone and website icon behaviour is unchanged.

Added the Flutter-maintained `url_launcher` dependency and refreshed package
metadata/lockfile with `flutter pub get`. No canLaunchUrl queries, location
permissions, map API keys, embedded map SDK or geocoding requests are used.
iOS/Android launch selection is implemented, but those platform targets are not
currently present in this checkout.

References:
- https://pub.dev/packages/url_launcher
- https://developer.apple.com/documentation/mapkit/unified-map-urls
- https://developers.google.com/maps/documentation/urls/get-started
